# V1.2 Work Evidence

Work Evidence is a typed, persistent record of user-visible proof of work. It
is separate from the append-only audit log and may be scoped to a mission or
task, or stand alone for routine/company activity.

`POST /work-evidence` accepts `source_type`, `evidence_type`, `summary`,
`content`, optional `mission_id`, `task_id`, `artifact_ref`, and metadata.
`GET /work-evidence` supports mission/task/source filters and bounded paging.
`GET /work-evidence/{id}` returns one record.

All content, metadata, summaries, and artifact references pass through the
structured redaction boundary before persistence. Authorization headers,
cookies, credential-bearing URLs (including Git remotes), environment-style
secret assignments, known token prefixes, and private-key blocks are removed.
Screenshots/artifacts must be submitted through this same endpoint; raw
artifact bytes are not stored as evidence.

Creation emits `work_evidence_created` and `work_evidence_redacted` audit
events. Audit payloads contain identifiers and types only, never source values.
