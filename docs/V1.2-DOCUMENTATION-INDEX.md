## Truth-source order

When documents disagree, use this order:

1. actual production/runtime/repository state,
2. current implementation/API contract,
3. current target plan + capability map,
4. security/evaluation rules,
5. current roadmap/operating model,
6. product specs,
7. historical architecture/release documents.

Never change a historical acceptance/release record to make it look as if a later capability existed at that time.
