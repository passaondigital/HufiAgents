# HufiAgents V1.3 Architecture — Persistent Workspace, Computer, Browser & MCP Adapter

**Date:** 2026-09-09  
**Target Release:** V1.3 ("Hufi gets hands")  
**Baseline:** V1.2.0 (`887ce6871da2f1fd420d1b0ecf4ae830941fab23`)  

## 1. Executive Summary

V1.3 expands HufiAgents with persistent per-agent computer and browser sessions, real browser automation evidence capture, a Model Context Protocol (MCP) tool adapter, and granular connector permission scope enforcement. All schema additions are strictly additive (`migration 008`), preserving complete backwards compatibility with V1.2.0.

## 2. Core Foundations & Session Lifecycle

### 2.1 Persistent Workspace & Computer Session Engine
- **Workspace Isolation:** Every agent operates in a dedicated, logical directory beneath `settings.workspace_root`.
- **File Safety Rules:** Strict path traversal protection (`..` escape blocked), symlink and hardlink prevention, and bounded read/write sizes (default 64KB per file, 100MB quota).
- **Session Lifecycle:** Persistent states: `prepared` -> `active` -> `snapshot` -> `reset` -> `recovered` -> `handoff` -> `closed`.
- **Snapshot & Reset:** Atomic directory snapshot backups stored beneath `.snapshots/` allow instant session state recovery or rollback without corrupting global data.
- **Session Handoff:** Session ownership transfer between agents issues explicit handoff tokens and creates immutable `Handoff` audit records.

### 2.2 Browser Automation & Work Evidence Integration
- **Retained Safe Sessions:** Browser state (cookies, current URL, active tab count) persists within isolated workspace storage.
- **Resource Guardrails:** Enforces `max_tabs` (1-8 tabs) and `memory_limit_mb` (64-2048 MB) boundaries per session.
- **Real Evidence Generation:**
  - `browser_dom`: Clean, sanitized DOM content logged directly to `WorkEvidence`.
  - `browser_screenshot`: Real SVG/image layout preview stored under workspace `screenshots/` and referenced via `WorkEvidence.artifact_ref`.
  - `browser_action`: Audited UI interaction events (`click`, `fill`, `select`, `new_tab`, `close_tab`).
- **Redaction Boundary:** All URLs, input fields, and page text pass through `redact()` before persistence.

## 3. Model Context Protocol (MCP) Adapter

### 3.1 Architecture
- **MCP Server Registration:** `MCPServerRegistration` tracks server transport (`stdio` or `http_sse`), command/URL, args, and risk mappings.
- **Tool Discovery:** `MCPToolDefinition` registers server tools with input/output schemas, required scopes, and capability risk ceilings (`R0`..`R4`).
- **Execution & Policy Gate:**
  - `R0`-`R1` actions: Auto-allowed if within agent's risk ceiling.
  - `R3`-`R4` actions: Trigger `policy_decision="approval_required"` and halt execution until human approval.
- **Evidence & Audit:** Invocation generates `ToolCall` events and sanitized `WorkEvidence` (`evidence_type="mcp_tool_result"`).

## 4. Connector Permission Scopes & Least Privilege

- **Granular Scope Verification:** `AgentConnectorAccess` grants explicit capability arrays, modes (`read`, `write`), and permission scopes (e.g. `repo:read`, `channels:write`).
- **Strict Membership Rule:** Organization or team membership **never** grants connector access automatically.
- **Risk Ceiling Rule:** Agent capability cannot escalate above `agent.risk_ceiling`.

## 5. Additive Persistence (`Migration 008`)

Schema additions introduce two new tables (`mcp_servers`, `mcp_tools`) and additive columns on existing tables:
- `computer_sessions`: `snapshot_path`, `handoff_token`
- `browser_sessions`: `current_url`, `active_tab_count`, `snapshot_path`, `handoff_token`
- `agent_connector_access`: `scopes`

## 6. Known Limitations

1. **Headless Browser Fallback:** When full GUI display engines are omitted, visual screenshots render structured DOM preview artifacts.
2. **MCP Stdio Isolation:** Stdio-based MCP subprocesses run in sandboxed subshells with strict environment redaction.
3. **Absolute Scope Boundary:** Zero interaction with `passaondigital/hufmanager` production, Supabase, DNS, or staging environments.
